# Evidenza — Preparazione dell'ambiente e metodo di lavoro

## Ambiente verificato

La postazione utilizza Windows con WSL 2 e una distribuzione Ubuntu supportata. I progetti sono conservati nel filesystem Linux e vengono aperti con Visual Studio Code tramite l'estensione WSL.

| Componente | Versione o stato pubblicabile | Verifica eseguita |
|---|---|---|
| WSL | WSL 2 | `wsl --status` |
| Ubuntu | 24.04 LTS | `lsb_release -a` |
| Visual Studio Code | Integrato con estensione WSL | Verifica interfaccia |
| Git in Ubuntu | 2.43.0 | `git --version` |
| Azure CLI | 2.90.0 | `az version` |

## Workflow completato

Ho clonato il repository del corso in locale e preparato la struttura nel repository personale `azure-devops-lab`. Tramite `git status` ho controllato i file non tracciati e le modifiche locali. Con `git add` ho aggiunto in area di staging l'evidenza e la nota operativa, isolando i file pertinenti. Successivamente il comando `git commit` ha registrato le modifiche nella cronologia locale con un messaggio descrittivo, e infine `git push` ha sincronizzato il tutto pubblicando il primo commit sul repository remoto di GitHub.
